# 事件订阅迁移规划（规范 20.3）

> 目标：把窗口控制从"高频轮询 xdotool/xprop"迁移到"X11/GDK 事件订阅"，
> 使桌面空闲 CPU 回归归零（规范 20.1：空闲 CPU ≤ 3%）。
> 本阶段为**过渡方案**：先确认/收敛轮询间隔 ≥200ms，再给出完整事件订阅迁移路径。

## 1. 当前轮询现状

| 文件 | 函数 | 当前间隔 | 单次开销 | 说明 |
|---|---|---|---|---|
| `/奇点OS/系统/界面.qd/图形图像桌面.qd/窗口.qd/win.qds` | `watch_minimize(on_minimized, interval=0.5)` | **500ms** | 每轮：`xdotool search` 枚举全部窗口 + 对每个窗口 `xprop WM_STATE` | 检测窗口最小化状态翻转 |

扫描结论：
- 全仓 `time.sleep / interval= / while True` 扫描（`qd_desktop.py`、`qd_fm.py`、`status_panel.py`、`窗口管理.qds`）未发现 <200ms 的高频轮询点。
- 唯一持续轮询为 `win.qds:watch_minimize`，间隔 0.5s，**已满足过渡要求（≥200ms）**。
- SLO 实测（`/奇点OS/运行/logs/slo_report.json`）：桌面三进程（xfdesktop/xfwm4/xfce4-panel）5s 采样合计 CPU ≈ 0.0%，当前无 CPU 热点。

### 过渡动作
- `win.qds:watch_minimize` 默认间隔保持 **0.5s（500ms）**，不做 <200ms 的高频改造。
- 后续若新增窗口监听，**禁止**引入 <200ms 轮询；统一走本规划的事件订阅路径。

## 2. 事件订阅方案（X11 / GDK）

### 2.1 事件类型映射
| 业务事件 | X11 事件 | GDK 等价 |
|---|---|---|
| 窗口创建/销毁 | `CreateNotify` / `DestroyNotify`（StructureNotify） | `window::added` / `window::removed`（GtkWindowManager / X11WM） |
| 窗口最小化/还原 | `PropertyNotify`(WM_STATE) 或 `StructureNotify` 状态位 | `window::state-changed`（GDK_WINDOW_STATE_ICONIFIED） |
| 窗口激活/焦点 | `FocusOut/FocusIn` 或 `PropertyNotify`(_NET_ACTIVE_WINDOW) | `window::focus-events` |
| 标题变化 | `PropertyNotify`(_NET_WM_NAME) | `window::title-changed` |

### 2.2 实现要点
1. 用 `XSelectInput(dpy, root, StructureNotifyMask|PropertyChangeMask)` 在根窗口订阅，
   或用 `wnck`/`GdkX11` 绑定 screen 信号（`window_opened`/`window_closed`/`window_state_changed`）。
2. 最小化检测：订阅目标窗口 `PropertyChangeMask`，只在 `WM_STATE` 属性变化时回调，
   替代"每 500ms 全量 xprop"。
3. 回调线程改为事件驱动（阻塞在 `XNextEvent` / GDK main loop），空闲时 0% CPU。
4. 与现有 `win.qds` 命令式接口（list/activate/minimize/close）并存：事件层只负责"推送通知"，
   命令层保持不变，避免破坏既有契约。

## 3. 迁移步骤
1. **试点**：在 `win.qds` 旁新增 `win_events.py`（不替换 `win.qds`），用 `wnck` 订阅
   `window_opened/closed/state_changed`，打印到 `/奇点OS/运行/logs/win_events.log`。
2. **双跑对照**：`watch_minimize`（轮询）与 `win_events`（事件）并行 1 个版本周期，
   核对两者检测到的最小化事件序列一致。
3. **切换**：事件层稳定后，把 `watch_minimize` 的回调接到事件源，轮询线程降为 5s 兜底心跳。
4. **下线轮询**：确认无遗漏事件后，删除 500ms 轮询循环，仅保留事件订阅。
5. **观测**：重跑 `slo_measure.py`，确认桌面空闲 CPU 仍 ≈0% 且事件无丢失。

## 4. 风险
| 风险 | 等级 | 缓解 |
|---|---|---|
| WNCK/GDK 依赖未安装 | 中 | 先 `apt list --installed | grep libwnck-3`；缺失则用裸 Xlib 事件兜底 |
| 事件订阅与 xfwm4 竞态（最小化瞬间属性未更新） | 中 | 事件回调内做一次一次性 `xprop` 确认，不做持续轮询 |
| 双跑期间日志翻倍 | 低 | 试点期日志走独立文件，纳入 logrotate |
| 事件层崩溃导致窗口监听静默失效 | 中 | 保留 5s 兜底心跳轮询作为看门狗，事件层缺失时告警 |
| 不碰 systemd unit / 安全配置 | — | 仅改动窗口模块代码与新增文档，不动服务定义 |
