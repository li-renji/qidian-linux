# 界面编辑器（界面.qd/界面编辑器.qd）立项书

> 版本：v1.0 ｜ 日期：2026-09-23 ｜ 状态：立项待评审
> 定位：奇点 OS 的 Figma / Adobe XD 式可视化界面设计器

## 1. 项目一句话定义

**界面编辑器是奇点 OS 内置的可视化界面设计工具**：用户像用 Figma/XD 一样，通过拖拽、点选、属性面板，直接设计/修改奇点 OS 的桌面界面（灵动岛、Dock、抽屉、窗口、壁纸、主题），**所见即所得，保存即生效，不需要改代码、不需要重装系统**。

## 2. 为什么做（问题与动机）

| 现状痛点 | 编辑器解决 |
| --- | --- |
| 界面是代码写死的（shell.qds），改界面=改代码 | 用户可视化拖拽，不碰代码 |
| 用户只能等我改，改一次等一次 | 用户自己随时改，立即预览 |
| 效果不满意只能反复描述、来回沟通 | 直接在设计画布上看到真实效果 |
| 界面风格高度绑定 GTK 主题 | 主题/配色/布局全部参数化，可自由定制 |

**与 AI.qd 的关系**：编辑器产生的界面配置（.json）可被 .qdai 规则读取/修改，即用户说的"用 AI 改界面"也走同一条配置通道——用户手动改和 AI 改，最终都是写同一份界面配置，互相兼容。

## 3. 交付物（做到什么样）

### 3.1 模块落地
```
界面.qd/界面编辑器.qd/
├─ 编辑器.html          # 主界面（Figma 式三栏布局：图层/画布/属性）
├─ 编辑器.js            # 编辑器逻辑（拖拽、选择、属性编辑、撤销重做）
├─ 编辑器.css           # 编辑器自身样式（深色主题）
├─ 渲染预览.html        # 实时预览（把配置渲染成桌面示意）
├─ schema.qds           # 界面配置 JSON Schema 校验器
├─ apply.qds            # 配置应用器（把配置推给 shell.qds / 主题系统）
├─ editor_ai.qdai       # AI 规则（AI 可读/改界面配置的契约）
└─ module.qdmeta
```

### 3.2 可编辑的对象（第一版范围）
| 对象 | 可编辑属性 |
| --- | --- |
| **全局主题** | 背景色、玻璃透明度、强调色、文字色、圆角半径、字体 |
| **灵动岛** | 位置（左/中/右）、高度、圆角、显示项（logo/状态点/时钟/日期）、状态点颜色 |
| **Dock** | 位置（底/侧）、图标集、图标大小、悬停效果、是否显示分隔符 |
| **抽屉** | 列数、卡片圆角、卡片背景、标题文字 |
| **最小化圆球** | 颜色、大小、光晕强度 |
| **壁纸** | 纯色 / 渐变色 |
| **窗口装饰** | 边框颜色、圆角（预留） |

### 3.3 编辑器界面（Figma 式三栏）
```
┌─────────┬───────────────────┬─────────────┐
│ 图层面板  │      画布          │  属性面板    │
│ (图层树) │  (拖拽/多选/对齐)   │ (Inspector) │
│         │                   │             │
│ - 灵动岛 │  [实时渲染的桌面]    │ 位置/尺寸    │
│ - Dock  │                   │ 颜色/圆角    │
│ - 抽屉  │                   │ 字体/阴影    │
│ - 圆球  │                   │             │
│ - 壁纸  │                   │             │
├─────────┴───────────────────┴─────────────┤
│ 工具栏: 选择 / 拖拽 / 文字 / 矩形 / 撤销 / 重做 / 保存 / 预览 │
└───────────────────────────────────────────┘
```

### 3.4 核心交互
- **拖拽**：鼠标拖拽移动对象位置
- **多选**：框选 / Ctrl+点选
- **属性编辑**：选中对象 → 右侧面板改数值/颜色（滑块、取色器、输入框）
- **对齐**：左对齐/居中/右对齐/顶对齐/垂直居中/底对齐
- **撤销/重做**：Ctrl+Z / Ctrl+Shift+Z（全操作可撤销）
- **图层排序**：上移/下移/置顶/置底
- **实时预览**：画布就是渲染结果，改完立刻看到
- **保存**：写回界面配置文件，shell.qds 热加载生效

## 4. 技术方案（怎么实现）

### 4.1 为什么用 Web 而不是 GTK 原生
| 方案 | 优劣 |
| --- | --- |
| **Web（HTML/JS）** ✅ | Figma 本身就是 Web 应用；拖拽/取色器/属性面板在 Web 生态最成熟；复用现有 webui.py(8080) 通道；与 AI.qd 的 JSON 配置天然同构 |
| GTK3 原生 | 拖拽画布/取色器/多选对齐在 GTK 实现成本高 3-5 倍，且与现有 Web 桌面预览割裂 |

**技术栈**：HTML + CSS + 原生 JS（零依赖，软渲染下性能可控）+ JSON Schema 校验 + 现有 webui.py 静态服务。

### 4.2 数据流（配置驱动）
```
用户在编辑器画布操作
  → 编辑器生成 界面配置 JSON（/奇点OS/系统/界面.qd/界面配置.json）
  → schema.qds 校验（非法配置拒绝保存 + 提示哪一项错）
  → apply.qds 把配置推给 shell.qds（热加载，立即生效）
  → AI.qd 通过 .qdai 规则也可读写同一份 JSON（人/AI 同通道）
```

### 4.3 渲染契约（shell.qds 改造）
shell.qds 从"代码写死样式"改为"读取配置渲染"：
- 启动时加载 `界面配置.json`
- 所有颜色/尺寸/位置从配置取值
- 监听配置变更（文件 watch / QD-IPC 消息）→ 自动刷新对应窗口
- 配置缺失/损坏 → 回退内置默认值（永不白屏）

## 5. 开发流程（透明 + 分阶段交付）

| 阶段 | 内容 | 交付/验收点 |
| --- | --- | --- |
| **P0 立项** | 本立项书 + 写入规范文档 | 用户确认立项书 ✅ |
| **P1 架构** | 界面配置 JSON 结构设计 + schema 校验器 + shell.qds 配置化改造 | 手动改 JSON → shell 生效 |
| **P2 编辑器骨架** | 三栏布局 + 画布渲染 + 图层树 + 属性面板框架 | 编辑器在浏览器可打开 |
| **P3 核心交互** | 拖拽 / 多选 / 对齐 / 属性编辑 / 撤销重做 | 能完整编辑一个对象 |
| **P4 配置闭环** | 保存→校验→应用→热加载 | 编辑器改完 → 桌面立即变 |
| **P5 打磨** | 取色器、图层排序、模板预设、AI 规则 | 全功能可用 |
| **P6 验收** | QEMU 软渲染实测 + 用户上手 | 用户通过 |

**每阶段交付方式**：每完成一个阶段 → 部署到 VM → 截图/视频给你验收 → 你说"过"才进下一阶段。不批量堆叠，避免问题积压。

## 6. 与你的交互方式

- **每阶段完成**：我会给出"做了什么 / 截图 / 怎么验收"三件套
- **你验收**：在 VNC 里实际操作（打开编辑器、拖一个元素、改个颜色、保存）
- **反馈**：你说哪里不对 → 我修 → 重新部署 → 你再看
- **过程中发现计划问题**：先停，跟你说明"计划要改哪里、为什么"，你同意才改

## 7. 问题解决预案（遇到问题怎么办）

| 风险 | 预案 |
| --- | --- |
| 软渲染下编辑器卡顿 | 减少实时重绘、操作后 200ms 防抖、画布降采样 |
| 配置改坏导致桌面异常 | schema 校验拒绝 + 自动备份上一次有效配置 + 一键恢复 |
| shell.qds 与配置不兼容 | 配置版本号 + 默认值兜底 + 兼容旧配置迁移 |
| 浏览器打开编辑器失败 | 走现有 webui.py 静态服务，先解决通道再开发功能 |
| 拖拽精度/多选复杂度超预期 | 砍范围：先保证单选+拖拽+属性编辑，多选/对齐后置 |
| 与现有 GTK 渲染差异大 | 画布用"配置值直渲"，保证编辑器看到的就是系统用的值 |

## 8. 验收标准（怎么算"完成"）

1. 在设置/抽屉中可以打开"界面编辑器"
2. 能拖拽灵动岛/Dock/圆球改变位置
3. 能改颜色（背景、强调色、状态点）、改圆角、改字号
4. 改完点保存 → 桌面立即变化，无需重启
5. 故意写坏配置 → 系统不崩，提示错误并可恢复
6. 全程中文界面
7. 软渲染下操作流畅（拖动跟手、无长时间卡死）

## 9. 不做的事（边界）

- 不做通用网页设计器（只针对奇点 OS 界面对象）
- 不做代码导出（用户不需要，配置 JSON 即最终产物）
- 不做动画时间线编辑器（第一版只做静态外观）
- 不引入第三方前端框架（零依赖，保证软渲染性能）
