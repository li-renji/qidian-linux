# 奇点OS 第四次重构 —— 从零构建方案 v1（存档）

> 来源：用户提供的完整全流程方案（2026-10-08）
> 定位：LFS 思想 + 模块化目标。Linux 内核 + 奇点OS 自制 rootfs，
>       自研 init，模块引擎为系统核心；不捆绑 Arch/Ubuntu，
>       需要哪个软件就单独编译源码，打包成 .qd/.qds 模块。

## 核心原则
- 编译环境：临时 Linux（本方案采用现有 arch.img VM 扩盘后作为编译机）
- Windows：只存源码、文档、脚本（第四次重构版目录）
- 版本选择：Linux 6.1 LTS / musl libc（轻量、静态链接优先）
- 交叉编译：x86_64-linux-musl-gcc（musl-cross-make 构建），
  防止宿主系统库污染奇点OS rootfs

## 大阶段划分
1. 准备编译宿主环境
2. 下载并编译 Linux 内核（6.1.115，defconfig + 裁剪，只留 ext4/tmpfs/virtio/VGA）
3. 构建交叉编译工具链（musl-cross，x86_64-linux-musl-gcc）
4. 搭建奇点OS最小 rootfs（sos-rootfs：bin/sbin/dev/proc/sys/tmp/usr/lib/modules）
5. 编写奇点OS自研 init（1号进程，主控）
6. 移植模块引擎、系统AI服务（module-engine，扫描 /modules 下 .qd/.qds）
7. 按需编译第三方组件（Xfce 等，打包 qds 模块）
8. 制作 ext4 镜像，QEMU 启动测试
9. 迭代模块总线、热插拔、白名单 AI 权限

## 启动链路（设计）
内核 → 挂载 sos-rootfs → 执行 /sbin/init → init 挂载 proc/sys/dev →
启动模块引擎 → 模块引擎扫描 /modules 下 .qd/.qds
→ 系统控制权从开机第一秒就在奇点OS代码手里

## 避坑清单
- 禁止宿主 glibc 直接编译程序进 rootfs（库版本不匹配 → 启动失败）
- 禁止编译 systemd 进系统（自研 init 是主控）
- rootfs 禁止直接拷贝 Debian/Arch 的 /usr（大量不兼容依赖）
- init.c 头文件必须 <sys/mount.h>（不是 <mount.h>）
- /dev 挂 devtmpfs（tmpfs 会覆盖 mknod 节点，console/null 丢失）
